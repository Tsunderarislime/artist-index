Version 2.2.0

  • Added a new image gallery feature. I want to provide an easier way to for visitors to discover artists they might like, so having a way to easily browse through all the artwork in the database made sense. This did add a new JavaScript library to the web application, though I made sure to restrict the import to just the image gallery.
  • Added a storage page for the control panel. Currently, it only displays the disk usage of file uploads. I may potentially add more to this in the future, maybe a simple file explorer? It really depends on how bad disk usage gets.
  • Adjusted images in artist view page to no longer use rounded corners. The parent container now prevents images from overflowing beyond the rounded corners of the container.
  • Fixed some styling inconsistencies between some of the pages.
  • Increased the minimum width of the main content container to 80%. This change mainly affects the desktop viewing experience. Previously, the main content would only take up roughly 65% of the viewport width, which was fine until I added the image gallery. It made sense to increase the minimum width of the main content for a better viewing experience overall, but it's particularly beneficial for the new image gallery.
  • Removed 'Add Artist' and 'Control Panel' from anonymous user view. There wasn't really any point to show these links to them, so I may as well remove them.

Version 2.1.1

  • Reformatted changelog version tracking to use three numbers instead of two, as some updates (like this one) are not big enough to warrant an X.1 version. I still want to track important things like bug fixes, so I added the third number for small updates like an X.Y.1 version.
  • Updated maintenance mode to properly return a 503 HTML status code.

Version 2.1.0

  • Added a new table for storing configuration variables. This fixed an issue with the recent maintenance mode where it would exit maintenance when the server woke up from sleep. As the free tier for Railway uses a serverless configuration, this was an issue that occurred when the web application was inactive.
  • Added a new script for loading in configuration variables from the configuration table.
  • Fixed an issue where private entries in the database could still be viewed if someone knew the exact name to enter in the address bar. Now it will redirect to a 404 page, maintaining the privacy of these artists.
  • Added character length limits to text forms to match the length limits of the strings in the tables.

Version 2.0.0

The second major version of the Artist Index is here. As this is a database of artists, I felt that it made sense to add a way to showcase some of their art.
  • Added a new table in the database for storing art data. This can either be a direct file upload or a direct image link from an image hosting service like Imgur or Reddit. The artist table has been updated accordingly.
  • Added a new config variable so that the file upload destination folder can be changed. An empty folder will also be initialized on startup.
  • Implemented file upload functionality. File uploads are renamed to a SHAKE-256 hash of that file for a unique filename.
  • Added an art carousel on the artist info page. This can be controlled by clicking on the buttons or swiping left/right if on a mobile device. Clicking on the image will take the user directly to the image's source.
  • Implemented add/edit/remove functionality for the art tables. Art is added on the artist info page, while editing/deletion is done through a new page.
  • Added a new page for editing/deleting art in the database. Edits to the direct links and source links can be made here, though direct image uploads can only have their source links modified. Deletion can be done in bulk by marking any art that is set for deletion.
  • Ensured that deleting an artist from the database also deletes all associated art from the database. This will also delete all image uploads for that respective artist.
  • Renamed some HTML templates in the 'artist' category to be more clearly distinguishable.
  • Added a config editor in the control panel. This is used to change the web application's config variables within itself.
  • Added a maintenance mode. During maintenance, access to the Artist Index is restricted for everyone except for administrators.

Version 1.0.0

This is the first major version of the Artist Index with all of the basic, main functionality of the index working.
  • Established the structure of artist database and the types of data to store in the database. SQLite was used as the database engine as traffic was not expected to be heavy.
  • Built the frontend using HTML, CSS, and JavaScript. Bootstrap CSS was used for styling the pages and automatically handling desktop/mobile clients.
  • Drew and animated the characters in the background.
  • Built the backend using Python and Flask. This was chosen due to being more familiar with Python.
  • Got the main index page to display the artist database in a table. Used the DataTables JS library for functionality like searching and sorting.
  • Added a user login system. No user registration was implemented on purpose, as logged-in users would be capable of modifying the database.
  • Added functionality for users to add, edit, and remove artists from the database.
  • Added a detailed view for artists which displays additional data. Logged-in users can additionally see hidden data that is not publicly available.
  • Added a control panel for users. The idea behind the control panel is to have a place that has all the administrative controls all in one page.
  • Added a password change form for users in the control panel. New passwords also need to be at least 8 characters long.
  • Added an "about" page, which has a link to the GitHub repository and a button to hide the interface.
